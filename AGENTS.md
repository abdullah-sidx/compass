# Compass: National Land Acquisition Control Tower

## What this is
A prototype for Smart India Hackathon 2026, problem statement SIH26016
("Real-Time National Land Acquisition & Management System for End-to-End Digital
Monitoring and Decision Support", Department of Land Resources, Ministry of Rural
Development). One web platform that tracks every land acquisition project and parcel
from proposal to handover, shows them on a GIS map, warns officials before a
project slips, and lets landowners see their own status.

Tagline: "Navigate land acquisition, on time."

## Core features (demo priority order)
1. Overview dashboard: KPIs, progress donut, parcels by status, top states,
   projects-at-risk table. Visual target: docs/reference/dashboard.png
2. GIS map: parcels coloured by status; click for ULPIN-keyed parcel details.
3. AI delay-risk: score per project, top reasons, "what-if" sliders.
4. Alignment checker: draw a corridor, see affected parcels, families and cost;
   compare two options.
5. Workflow + audit: stage approvals by role, deadline countdowns, hash-chained log.
6. Landowner portal: search by ULPIN, status, grievance form, English/Hindi/Kannada.
7. (Stretch) Offline field app.

## Stack
Next.js (App Router), TypeScript, Tailwind CSS, MapLibre GL JS, turf.js, Recharts.
The risk model is trained offline in Python and exported to JSON; inference runs
inside the app. No external backend, no database server (seed data + in-memory
state, mirrored to localStorage where state must survive a refresh).

## Hard rules
- ALL data is synthetic, generated by the seed script with a fixed random seed.
  Never use real personal data. Show a small "Sample data" label where it matters.
- No hardcoded figures in components. Every number comes from /lib/data.ts or the
  API routes. Shared types live only in /lib/types.ts.
- No real integrations (Land Stack, Bhoomi Rashi, PFMS, PARIVESH). If shown in the
  UI they are clearly labelled "mock adapter".
- Colour legend everywhere: Notified = blue, Under assessment = amber,
  Compensation paid = green, Possession completed = purple, Delayed / at risk = red.
- Light theme, white cards, subtle borders, rounded corners. Desktop first (1280px+).
- The ULPIN is a 14-character alphanumeric parcel ID. Generate it consistently.
- Do not add dependencies without noting the reason in PROGRESS.md.
- Work on ONE chunk at a time. Never start the next chunk unprompted.
- Prefer small, readable files. No giant components; split by feature.
- Never claim in the UI that this is an official government system.

## Definition of done (every chunk)
1. `npm run dev` runs and `npm run build` passes (type errors fixed).
2. No console errors on the pages touched.
3. The chunk's acceptance line is met.
4. PROGRESS.md is updated (Done / Next / Decisions / Known issues).
5. Changes are committed with a clear message.

## Honest-prototype notes (for UI copy and docs)
- The delay-risk model in this prototype is an interpretable linear model trained
  on synthetic data. A production system would train on real pilot data.
- Statutory deadlines are generic stage SLAs, not legal advice. Do not cite
  specific sections of the land acquisition law in the UI.
